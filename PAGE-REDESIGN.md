# PAGE REDESIGN

## Goal

Упростить страницу, убрать около 80% текста, перевести основную подачу в визуальные носители и сохранить уже собранную смысловую воронку.

Новая логика:

- `hero` остаётся технологичным, современным, чистым
- все блоки ниже уходят в packaging-industrial стиль
- основным носителем смысла становятся иллюстрации, схемы, ярлыки, штампы, карточки, маркировка
- текст остаётся только там, где без него теряется управленческий смысл

## Current Meaning Structure

Текущая структура правильная и сохраняется по смыслу:

1. `Hero`
2. `Scenarios`
3. `Assortment`
4. `Economics`
5. `FAQ`
6. `Order`

Это не нужно ломать. Нужно поменять форму подачи.

## Core Meanings To Preserve

Во всех версиях страницы нужно удержать эти смыслы:

- продукт помогает добавить горячее без новой кухни или тяжёлой операционки
- продукт подходит не всем подряд, а конкретным рабочим ситуациям
- старт должен быть маленьким и управляемым
- запуск нужно показывать как понятный сценарий, а не как сложный процесс
- экономика и вход должны считываться быстро
- возражения должны сниматься коротко и жёстко
- финал страницы должен вести к тесту или пилоту

## New Visual Direction

### Hero

Сохраняется как отдельный технологичный слой:

- белый или почти белый фон
- clean UI
- 3D-подача продукта
- современная типографика
- минимум упаковочного шума

Что остаётся:

- логотип
- навигация
- оффер
- короткий подзаголовок
- 2 CTA
- 3D-пицца

Что уходит:

- факт-чипы под заголовком

### Packaging Zone

Всё ниже hero работает как второй визуальный мир:

- тёплая бумага
- ощущение печатного носителя
- текстуры бумаги
- чёрная типографика
- красно-оранжевые акценты
- штампы, коды, маркировка, техлисты, ярлыки

Важно:

- это не винтаж
- это не кафе-крафт
- это industrial packaging / shipment / print system

## New Page Structure

### 1. Hero / Tech Layer

Назначение:

- быстро показать продукт
- быстро показать бизнес-пользу
- открыть путь к заявке

Состав:

- логотип и навигация
- оффер
- короткий подзаголовок
- 2 CTA
- 3D-визуализация

Принцип:

- текста мало
- всё должно считываться за несколько секунд

### 2. Transition Strip

Новый короткий переходный блок между `hero` и бумажной частью.

Назначение:

- переключить визуальный режим
- подготовить переход от digital-tech к packaging-paper

Состав:

- узкая полоса или короткая секция
- batch-коды
- SKU
- frozen / horeca / retail
- маркировка
- печатные символы

Текста почти нет.

### 3. Use Cases / Packaging Posters

Заменяет текущий `Scenarios`.

Назначение:

- показать, где продукт нужен
- убрать длинные текстовые объяснения

Новая форма:

- 3-4 визуальные постер-карточки
- каждая карточка = одна ситуация
- одна короткая фраза
- одна иллюстрация
- 2-3 маленьких смысловых маркера вместо абзаца

#### Horeca meanings

- гость уходит за горячим
- не хотят заводить новую кухню
- горячее нужно по ситуации
- сначала хотят проверить спрос

#### Retail meanings

- нужен понятный SKU
- нужен безопасный пилот
- нужна повторяемая операционка
- важно масштабирование

### 4. Format Sheet / Product Lineup

Заменяет текущий `Assortment`.

Назначение:

- показать стартовый набор
- объяснить, с чего начинать

Новая форма:

- лист комплектации
- карточки как упаковочные лейблы или product tags
- минимум слов
- один формат = одна функция

#### Horeca

- 2 понятных вкуса
- 1 акцентный вкус
- визуально как стартовый набор для теста

#### Retail

- 3 понятных формата входа
- подача как SKU-sheet / format sheet

### 5. Flow / How It Works

Новый блок.

Часть текущих смыслов из `Scenarios` и `Economics` нужно собрать в одну наглядную схему.

Назначение:

- объяснить процесс быстрее текста
- показать, что запуск простой и короткий

Новая форма:

- схема
- стрелки
- пиктограммы
- короткие подписи

#### Horeca flow example

- морозилка
- печь / конвектомат
- выдача гостю

#### Retail flow example

- пилот
- проверка спроса / category fit
- масштабирование

### 6. Business Snapshot / Economics Card

Заменяет текущий `Economics`.

Назначение:

- быстро донести экономическую модель
- убрать длинную расшифровку

Новая форма:

- один сильный бумажный лист
- 3-4 цифры или маркера
- одна центральная карточка
- минимум пояснений

#### Horeca

- минимальный вход
- закупка
- цена в меню
- потенциал

#### Retail

- pilot
- SKU
- category fit
- масштабирование

### 7. Objections / Stamped Answers

Заменяет текущий `FAQ`.

Назначение:

- снять барьеры без длинных раскрывашек

Новая форма:

- 3-4 карточки-штампа
- короткое возражение
- короткий жёсткий ответ

Принцип:

- не accordion
- не длинный FAQ
- не объяснение на абзац
- только быстрое снятие барьера

### 8. Contact Sheet / Order Form

Остаётся финальным блоком вместо текущего `Order`.

Назначение:

- собрать заявку
- завершить воронку

Новая форма:

- бланк заявки
- поля как form sheet / request card
- меньше поясняющего текста
- сильнее ощущение official pilot request

## Text Reduction Rules

### Remove

Нужно сократить:

- длинные описания секций
- длинные тексты в карточках сценариев
- многословные подписи в ассортименте
- разжёванные пояснения в economics
- длинные ответы в FAQ
- вторичные повторяющиеся объяснения

### Keep

Оставлять только:

- один сильный заголовок
- одну короткую расшифровку
- ключевые цифры
- короткие маркеры
- CTA

## Illustration Rules

Иллюстрации должны быть не декоративными, а смысловыми.

Подходящие типы:

- упаковочные постеры
- product labels
- shipment cards
- техкарты
- equipment icons
- схема процесса
- визуалы коробки, маркировки, стикеров
- условные отгрузочные документы

Неподходящие типы:

- случайные lifestyle-иллюстрации
- абстрактный decor-only noise
- ретро-декор ради ретро
- уютный крафт-стиль без ощущения B2B и продукта

## Mapping From Current Blocks

- `Hero` -> сохранить, но убрать факт-чипы
- `Scenarios` -> превратить в visual use-case posters
- `Assortment` -> превратить в packaging lineup / sheet
- `Economics` -> сократить до snapshot card
- `FAQ` -> превратить в stamped answers
- `Order` -> оставить как form sheet

## Execution Notes

Переделку лучше делать поэтапно:

1. обновить структуру и фоновые миры страницы
2. собрать transition block
3. переделать `Scenarios` и `Assortment` в визуальные секции
4. добавить `Flow`
5. сократить `Economics`
6. заменить `FAQ`
7. упростить `Order`

## Success Criteria

Редизайн считается успешным, если:

- страница стала заметно легче по тексту
- смысл не потерян
- hero и packaging-zone визуально контрастируют
- ниже hero страница ощущается как единая упаковочная система
- пользователь за несколько секунд понимает продукт, сценарий входа и следующий шаг

## Implemented

Ниже зафиксировано, что уже реально внесено в код.

### Structure

- обе сегментные страницы переведены на общую data-driven систему секций
- сохранена смысловая последовательность:
  `use cases -> lineup -> flow -> business snapshot -> objections -> final offer`
- длинные текстовые блоки удалены или радикально сокращены

### Hero

- `hero` оставлен отдельным современным слоем
- hero возвращён к центральной композиции
- чипы-факты под оффером удалены
- логотип переведён на `IBM Plex Serif`

### Packaging Zone

- ниже hero включён отдельный бумажный визуальный мир
- добавлена деликатная бумажная текстура через CSS background
- визуальный язык переведён из карточек в более жёсткую линейную систему
- основная смысловая масса собрана в левой колонке примерно на две трети ширины

### Grid

- paper-zone переведена на швейцарскую композицию с жёсткой сеткой
- убраны вложенные плашки и декоративные панели внутри панелей
- согласован вертикальный ритм для высоты экрана MacBook
- вторичный серый текст убран, текстовая система переведена в чёрный

### Final Offer

- финальный блок очищен от служебного текста над формой
- оффер и форма объединены в единый closing block
- блок выведен в центр и стилистически сближен с hero
- в финальную плашку добавлена маленькая low-res 3D-пицца

### Technical

- сегментные страницы загружаются лениво
- `HeroPizzaModel` расширен для low-res режима и повторного использования
- дублирующаяся шапка была убрана
- сборка `npm run build` проходит
